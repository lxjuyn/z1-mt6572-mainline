# Z1 静态 adbd 规划 (2026-08-15)

> 只读 + 联网分析产物。目标: 设备端静态 adbd 二进制的获取/编译方案 + 可行性评估 + 替代建议。
> 配套内核侧规划见 `ADB_KERNEL_20260815.md`(f_fs 方案, CONFIG_USB_CONFIGFS + CONFIG_USB_CONFIGFS_F_FS, UDC=musb-hdrc)。
> 结论一句话: **设备端 adbd 只有一条现实路径 = AOSP adb 源码 + Linux 化补丁交叉编译(functionfs 模式), 完整可复刻配方就在 meta-openembedded android-tools(scarthgap)里; 且本机已有一份 fully-static + FunctionFS 的原厂 adbd 可零编译先用。**

## 1. 候选来源评估

### 1.1 AOSP adbd(system/core/adb)— 可行, 但要补丁 ✅
- 设备端 adbd 源码就在 AOSP `system/core/adb`(`adb.c`/`services.c`/`transport_usb.c`/`usb_linux_client.c`/`file_sync_service.c`/`jdwp_service.c`/`framebuffer_service.c`…), 纯 C, 可交叉编译, 不依赖 Android runtime。
- 难点: 依赖 liblog / libcutils / libselinux / `build` 头(`AndroidConfig.h`) 与 bionic/property/log 纠缠; 官方 Soong 不能脱离 Android 树 → 需要一份"Linux 化补丁集"。
- **已核实关键点**(决定这条路线是否成立): android-5.1.1_r37 commit `2314b110…` 的 `usb_linux_client.c` 含**完整 FunctionFS 支持** —— `usb_init()` 里 `access(USB_FFS_ADB_EP0,F_OK)` 命中 → 走 `usb_ffs_init()`: 打开 ep0, 写 ADB 描述符(interface class 0xff ADB_CLASS/SUBCLASS/PROTOCOL + 2 个 bulk 端点 + "ADB Interface" 字符串), 再开 ep1/ep2 泵数据。**与我们的内核 f_fs 方案完全对齐**(/dev/usb-ffs/adb/ep0..ep2)。

### 1.2 meta-openembedded android-tools 配方 — 推荐(即 1.1 的可复刻成品)✅
- `meta-oe` scarthgap 分支:`meta-oe/recipes-devtools/android-tools/android-tools_5.1.1.r37.bb`(另 master 有 29.0.6.r14 / 35.0.2)。
- 它**就是从 AOSP android-5.1.1_r37 git 固定 SRCREV + 17 个 Linux 化 patch + 自定义 mk 文件**, 交叉编译出可在普通 Linux 上跑的 `adbd`(Yocto 生产级, 已用多年)。所有 URL 本次已实测 200 可达。
- `adbd.mk` 就是给我们的编译配方(见 §3.3), 已含: remove-selinux / **musl-fixes**(0006)/ **allow-adbd-root**(0008)/ define-shell-command(0003)/ libssl_11 diff。
- 链接 `-lpthread -lbsd -lpcre -lresolv -lcrypto`(recipe DEPENDS 另含 zlib libcap)。

### 1.3 简化/独立 adbd 项目 — 不推荐
| 项目 | 结论 |
|---|---|
| **nmeum/android-tools**(Alpine/Arch/Gentoo 的 android-tools port) | **只做 host 侧 `adb`+`fastboot` 等工具, 明确无 adbd**; 且 Alpine 官方只编 **x86_64**(armv7 无)。方向反了, 不用。 |
| **qhuyduong/arm_adb** | 老(2015)automake 移植, **host adb client**, 不含设备侧 adbd; 锁 openssl-1.0.2l。 |
| **prife/adb** | AOSP adb standalone(cmake), 只支持 x86-64/arm64, 无 arm32 设备侧 adbd。 |
| **hadess/adbd** | 现代 AOSP adbd fork(带 `ADB_NON_ANDROID`), 但无 README/无构建指引, 不成熟。 |
| **busybox** | 无 adbd。 |

### 1.4 发行版二进制 — 已死路
- Debian/Ubuntu 的 `android-tools-adbd` **已从全部 suite 移除**(packages.debian.org / packages.ubuntu.com focal+armhf 均 0 结果)。即使有也是 glibc 动态 → Alpine musl 跑不了。结论: 别等发行版, 自己编。

## 2. 推荐: 构建路径 A(编)— meta-oe 配方静态交叉编译

### 2.1 源获取(只读步骤, 实施时执行)
```bash
# 1) 配方文件(从 meta-openembedded, scarthgap 分支)
BASE=https://raw.githubusercontent.com/openembedded/meta-openembedded/scarthgap/meta-oe/recipes-devtools/android-tools/android-tools
#    需拉: android-tools_5.1.1.r37.bb、adbd.mk、gitignore、android-tools-adbd.service、
#    core/0001..0017 补丁 + core/adb_libssl_11.diff + core/b64_pton_function_decl.patch
#    build/extras/libselinux 补丁、build 的 riscv patch(仅 riscv 用, arm 可略)

# 2) AOSP 源树(git, 固定 SRCREV = android-5.1.1_r37)
git clone https://android.googlesource.com/platform/system/core      && cd core && git checkout 2314b110bdebdbfd2d94c502282f9e57c849897e
git clone https://android.googlesource.com/platform/system/extras     # 3ecbe8d841df96127d7855661293e5ab6ba6c205
git clone https://android.googlesource.com/platform/hardware/libhardware # be55eb1f4d840c82ffaf7c47460df17ff5bc4d9b
git clone https://android.googlesource.com/platform/external/libselinux  # 07e9e1339ad1ba608acfba9dce2d0f474b252feb
git clone https://android.googlesource.com/platform/build               # 仅取 build/core/combo/include/arch/linux-arm/AndroidConfig.h
```
(完整源也可直接拿 Ubuntu `android-platform-system-core`/`android-tools` orig 包当备料, 但 meta-oe 的 SRCREV 更精确可控。)

### 2.2 静态依赖库
`adbd.mk` 链接 `-lpthread -lbsd -lpcre -lresolv -lcrypto`(recipe DEPENDS 另含 zlib、libcap)。三选一:

- **A1: glibc static(用现有 `arm-linux-gnueabihf-gcc`, 最省事)**
  ```bash
  sudo dpkg --add-architecture armhf
  sudo apt-get update
  sudo apt-get install libssl-dev:armhf zlib1g-dev:armhf libbsd-dev:armhf \
                       libpcre3-dev:armhf libcap-dev:armhf
  # 注意 libssl-dev:armhf 给 1.1/3.x 头; adbd 5.1.1 需 OpenSSL 1.0 API,
  # 必须带 meta-oe core/adb_libssl_11.diff 补丁兼容 1.1。
  # 若不想依赖发行版交叉包, 自编 openssl-1.1.1w:
  #   CC=arm-linux-gnueabihf-gcc ./Configure linux-armv4 no-shared no-tests --prefix=$SYSROOT
  #   make && make install_sw   → 产出 libcrypto.a / libssl.a
  ```
  链接时 `LDFLAGS += -static -static-libgcc` → 纯静态 glibc 二进制, 在 Alpine/musl 上无 glibc 也能跑(静态 glibc 自包含)。

- **A2: musl static(更贴 Alpine, 体积最小)**
  ```bash
  sudo dpkg --add-architecture armhf
  sudo apt-get update && sudo apt-get install musl-tools:armhf   # → arm-linux-musleabihf-gcc
  # 0006-adb-Musl-fixes.patch 已在配方里 → 源码天然过 musl
  ```
  musl 静态 → 零 glibc 依赖、无 NSS 坑, 与目标 rootfs 一致, 首选。若 musl-tools:armhf 不可用, 用 musl-cross-make 现编。

- **A3: 动态 musl(装 Alpine 包)** — Alpine armv7 有 openssl/libbsd/libpcre/zlib/libcap, 动态链接也成; 但既然静态零依赖, 不做为默认。

### 2.3 编译命令骨架(实施阶段按配方 do_compile 逐条补齐)
```bash
export S=/path/to/android-tools-git        # 已 apply 全部 core/extras/libselinux 补丁的源树
export android_arch=linux-arm
mkdir builddir && cd builddir
make -f adbd.mk SRCDIR=$S \
     CC=arm-linux-gnueabihf-gcc AR=arm-linux-gnueabihf-ar \
     LDFLAGS="-static -static-libgcc"
# 产出 builddir/adbd —— file 应报 "statically linked", readelf -l 无 INTERP
```
要点(配方已确认):
- CFLAGS 必须含 `-DADB_HOST=0 -DALLOW_ADBD_ROOT=1 -DANDROID -D_GNU_SOURCE`, include 路径覆盖 `system/core/adb`、`system/core/include`、`system/extras/ext4_utils`、`system/core/fs_mgr/include`、`hardware/libhardware/include`、`external/libselinux/include`, 且 `-include $(S)/build/core/combo/include/arch/linux-arm/AndroidConfig.h`。
- 若换 glibc → openssl 用 1.1.x 时带上 `adb_libssl_11.diff`。

### 2.4 运行时需求(与内核无关, 上板才用)
- 内核侧已挂 functionfs 后(见 ADB_KERNEL_20260815.md §5.4), 用户态:
  1. 挂 configfs → 建 gadget(`idVendor=0x18d1`, product 建议 0x4ee2/0xd002)→ `functions/ffs.adb` → `mount -t functionfs adb /dev/usb-ffs/adb`(可同时加 `functions/acm.usb0` 保留串口)→ `echo musb-hdrc > UDC`。参考脚本: meta-oe `android-tools-conf/android-gadget-setup`(vendor=0x18d1, ffs 挂 /dev/usb-ffs/adb)。
  2. adbd 以 root 起(`ALLOW_ADBD_ROOT=1`, 不再降权/不再要 shell 用户)。
  3. `adb shell` 要 `/system/bin/sh` → initramfs 里 `mkdir -p /system/bin && ln -sf /bin/sh /system/bin/sh`(0003-define-shell-command patch 已处理, 但路径仍硬编码 /system/bin/sh)。
  4. auth:`ro.adb.secure` 未设 → 5.1.1 默认不要求 RSA → 免 adb_keys; 若被拉高, 放 `/data/misc/adb/adb_keys` 或跑一次 `adb keygen`。
- **static 自包含 + 内核只开 f_fs → vermagic/内核无关, 不影响现有 CONNSYS .ko。**

## 3. 备选路径 B(零编译): 复用原厂静态 adbd — 首选先试
- **已核实**: `out/boot_extracted/rd/sbin/adbd` = static ELF ARM EABI5, `file` 报 statically linked, `readelf -l` 无 INTERP/NEEDED/.dynamic → 纯静态, 拷进 Alpine initramfs 即可运行。
- **已核实 functionfs**: strings 命中 `/dev/usb-ffs/adb/ep0/ep1/ep2` + `[ usb_init - using FunctionFS ]` + `init_functionfs` → 与我们的内核 f_fs 配置一致, 直接能走 functionfs 路径。
- **风险清单(Android 残留, 需缓解)**:
  1. **property 服务**: 读 `ro.adb.secure`/`ro.debuggable`/`ro.product.*`/`service.adb.tcp.port`。`/dev/__properties__`、`/dev/socket/property_service` 不存在 → property_get 返回空。`ro.debuggable` 空 → 判 production build → 不降权则 `setuid("shell")` → Alpine 无 shell 用户 → **需 `adduser shell`(uid/gid 2000) 或建假属性层**。
  2. **`/dev/log/main`**: log 通道缺失可能静默降级(实测为准; 可 `mkdir /dev/log` 兜底)。
  3. **`/system/bin/sh` 硬编码**(adb shell 用)→ `ln -sf /bin/sh /system/bin/sh`。
  4. tzdata(`/system/usr/share/zoneinfo/tzdata`)只影响时间戳, 可忽略。
  5. 它按 `ro.adb.secure` 空值默认不走 RSA(与 §2.4 同理), 大概率免认证。
- 优点: **零编译、零新依赖、行为与 2022 原厂一致**。缺点: Android 残留不可控, 失败排查成本高于自己编。

## 4. 替代方案评估

### 4.1 (a) 极简 functionfs 交互(不用 adbd)— 不推荐
- 想替代 adbd 需自己实现 ADB 协议(CNXN/OPEN/OKAY/SYNC/framing)+ 写 f_fs 描述符, 工作量 ≈ 完整 ADB server, 且 host 侧标准 `adb` client 才认得。没有现成靠谱的轻量实现(独立项目都太玩具)。
- 退化为"functionfs 双向泵到 pty"→ 那就等价于 ACM 串口, 不如直接用现成 ACM。**结论: 不划算。**

### 4.2 (b) 用现成 USB ACM(ttyGS0)— 最简单, 先落地
- Z1 已有 USB-CDC ACM 通路(`g_serial`→ttyGS0, 见 CLAUDE.md 路C)。只需修 termios(raw 模式、关 echo、波特率)当 USB 串口用, host 侧 `screen`/`minicom`/`socat` 直连。
- 无 `adb push/install`, 但 shell + 文件传输(rzsz/zmodem 或直接 shell)够用。
- **注意: configfs 方案里 ACM 与 adb 同 composite 可共存**(ADB_KERNEL_20260815.md §2 方案1)→ 修 ACM 不阻塞后续上 adbd。
- 若需求只是"交互 shell + 抓 log"→ 这条 1 小时内可用, 应并行先做。

### 4.3 附: adbd TCP 模式(绕过 USB)
- 编译好的 adbd 设 `service.adb.tcp.port=5555`(或 `adb tcpip 5555`)→ host `adb connect <ip>:5555`。需 Z1 有网(Wi-Fi 待上板)。作为 USB functionfs 之外的第二通道, 同样依赖 §2/§3 的 adbd。

## 5. 推荐路线(给主会话)
1. 内核侧: 按 ADB_KERNEL_20260815.md 开 `CONFIG_USB_CONFIGFS`+`CONFIG_USB_CONFIGFS_F_FS`+`CONFIG_USB_CONFIGFS_ACM`, 关 `USB_G_SERIAL`, 上板确认 `/sys/class/udc/musb-hdrc` + `mount -t functionfs` 能出 ep0/ep1/ep2。
2. **设备侧先用路径 B(原厂静态 adbd)**: 零编译拷入 initramfs, 配 configfs setup 脚本 + `/system/bin/sh` symlink + `adduser shell`, 抓 log 验证 `adb devices`。
3. B 因 Android 残留失败 → **路径 A(§2)**: 拉 meta-oe android-tools 配方, `arm-linux-gnueabihf-gcc -static`(或 musl 静态)编出干净 adbd, 替换。
4. **并行低风险**: 先修 ACM termios(§4.2)作兜底交互通道, 不阻塞。
5. 产物纪律: adbd 编出/拷出后 `file`+`readelf -l` 验证 static, 立刻归档 `bridge_backups/products/` + git 上传。

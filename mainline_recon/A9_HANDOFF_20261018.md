# A9 交棒链（P9，2026-10-18）—— 不等 AOSP ramdisk，也能把 A9 system 拉起来

## 1. 这一步解掉的是哪个死结

A9 的正常启动链是 `boot.img 里的 first-stage init` → 挂 `/system` → 载 SELinux 策略 →
`exec /system/bin/init second_stage`。mainline 线原本把"拿到 A9 generic ramdisk（first-stage）"
当作必须靠另一台机器交付的前置条件（`A9_SYSTEM_MIGRATION_CHECKLIST.md` 第 5 节第 2 步）。
本机出网面取不到那份原料（复测见 `A9_SYSTEM_ADAPT_20261018.md` §8：`download.lineageos.org`
对任何路径都回同一份 723 B Vue 壳，`update.lineageos.org` 连 DNS 都不解析，
`blob.lineageos.org` 是真能下文件但只有 twrp/heimdall 不放 ROM）。

于是 P9 把 first-stage 的**必要职责**搬进我们自己的 bring-up ramdisk：
`tools/z1/z1_a9_handoff.sh`。结果是 —— **手里只要有一份 arm32 A9 的 system.img，
我们的 boot.img 就能直接把它拉起来**，不再等第二台机器打 ramdisk。

## 2. 判据与动作（两阶段，可分别验证）

`z1_a9_handoff.sh probe`（只读，exit 0=可交棒）：
1. 认 android 分区：**先按分区字节数**匹配 scatter 的 `android`=943,718,400 B，
   再退回 `uevent` 里的 `PARTNAME=android`。不靠设备号猜，也不依赖 mdev 造 by-name/by-partlabel
   （本树 + busybox mdev 不保证给）。
2. 只读挂上 `$SYSROOT`（默认 `/system`；**已有内容就跳过挂载**，保证重复执行安全、也让本机
   免 root 能拿目录夹具测判据）。
3. `build.prop` 用遍历找，不猜层级：`ro.build.version.sdk` 必须 28；
   `ro.product.cpu.abi` 含 arm64 直接拒（本树 `ARCH=arm`，32 位内核跑不了 64 位 ELF）。
4. 找到 `$SYSROOT/bin/init` 或 `$SYSROOT/system/bin/init`，读 **ELF 头 `e_machine`**：
   必须 `0x28`(EM_ARM)。属性会骗人，ELF 头不会 —— 与 `z1_a9_system_accept.py` 同源的第二路证据。

`z1_a9_handoff.sh go`（判定通过后才调）：
1. 补 `/dev/block/by-name/{system,cache,bootimg,userdata}` 符号链接 —— A9 的 fstab/ueventd
   全靠这些名字，而本树 + busybox mdev 不生成。
2. 只读 `noatime` 挂 `/system`；`/system` 里还嵌一层 `system/` 时 bind 下移（system-as-root 形态）。
3. **把 vendor 换成可写的**：A-only 的 LOS16 把 `/vendor` 塞在只读 system 里，而 A9 second-stage
   只在 `/vendor|/odm|/product/etc` 下找 `fstab.<ro.boot.hardware>`。所以先试 tmpfs+整份拷
   （tmpfs 大小按 `du -sk` 实算 +48m 余量），挂不上就退回 bind，两者都失败就如实报
   `RESULT_STEP_vendor=UNMOUNTED` 并**继续**按目录现状准备 fstab —— 不把两件事混成一条结论。
4. **fstab 落位**：机型名从 `/proc/cmdline` 的 `androidboot.hardware=` 取（与 A9 同源，不硬编码 z1），
   从 `/system/etc/fstab.<hw>`（device 层那份）拷到 `/vendor/etc/fstab.<hw>`；
   分别报 `OK / PLACED / MISS / FAIL`。
5. **补做 first-stage 的 SELinux 职责**：挂 selinuxfs → 找 `precompiled_sepolicy`
   （cil 需要 secilc，板上编不动，所以只认预编译件）→ `cat > /sys/fs/selinux/load` →
   报 `LOADED(路径 + 精确字节数) / FAIL / NOPOLICY / SKIP`，最后兜一次 `enforce=0`
   （dts 已有 `androidboot.selinux=permissive`，这是双保险）。
6. `exec "$INIT" second_stage` 顶掉 PID 1。

`/init`（v13.9-a9hand）把交棒放在**探针与 config.gz 自证之后、ACM/getty 之前**：
- 判定不过 → 原样落回调试 shell，所以这张镜像对"只刷 boot"的旧用法零风险；
- 判定过 → `exec`，串口继续输出 A9 init 自己的日志。
顺带修了一处真实缺陷：`[a9dev]` 运行时节点段原先写在 `[ -e /proc/config.gz ]` 的 **else 分支**里，
也就是 `CONFIG_IKCONFIG_PROC` 一生效这些节点证据就永不打印。现在搬出来无条件执行。

## 3. 本机实测证据（免 root，全绿）

`bash tools/z1/z1_a9_handoff_selftest.sh` 8/8 全绿（假 sysfs + 目录夹具 + 假 selinuxfs，
`VENDROOT/SELINUXFS/BYNAME/SYSROOT/NODEPREFIX` 全部可用 `Z1_*` 环境变量改指向，所以免 root）：

```
1) arm32 A9(sdk=28) 齐备            -> RESULT_STEP_handoff_probe=GO
2) 原厂形态 sdk=19                  -> FAIL(sdk=19 不是 28，不交棒)
3) A9 但 abi=arm64-v8a              -> FAIL(abi 是 arm64，本内核 32 位跑不了)
4) 属性写 arm32、ELF 却改成 arm64    -> FAIL(e_machine 不是 EM_ARM(退 3)，交棒必 SIGILL)
5) 没有 943,718,400 B 的分区         -> SKIP，不许乱挂
6) 只有 PARTNAME=android、无 size    -> 走 uevent 兜底，GO
7) go 的接线全链：by-name 4 条建成、vendor 报 UNMOUNTED(非 root 挂不上，符合预期)、
   fstab=PLACED(/vendor/etc/fstab.z1 自 /system/etc/fstab.z1，文件真的落盘并比对过)、
   selinux=LOADED(26 B 假策略喂进 load，用 cmp 逐字节核对过)、enforce 被写成 0、
   最后打到 RESULT_STEP_handoff=EXEC
8) 抽掉 fstab 与 selinuxfs           -> fstab=MISS、selinux=SKIP 都如实点名，不静默
HANDOFF_SELFTEST=ALL_PASS
```

出片链（`tools/z1/z1_a9_mkramdisk.sh`：装配前 `busybox sh -n` 静态门 + 打包后从成品 .gz
回读对账，`CHK_FAIL=0`）：

## 4. 板上要读什么（刷 boot-only 包也照样有信息）

串口（921600）里按顺序应看到 `[init]` → `[pstore]` → `[a9dev]` → `[a9probe] RESULT_STEP_*` →
`[a9cfg]` → **`[a9hand]`**：

| 串口标记 | 含义 | 下一步 |
|---|---|---|
| `RESULT_STEP_handoff_probe=SKIP(没有尺寸=…)` | android 分区没被认出来 | 看 `[a9dev]`/dmesg 里 mmcblk0p* 是否齐；几何表要跟着 scatter 复核 |
| `…=FAIL(挂不上 ext4)` | p4 不是 ext4 或还是原厂 4.4 的别的形态 | 先确认 system 刷进去了 |
| `…=FAIL(sdk=… 不是 28)` | 分区里不是 A9 | 正常（只刷 boot 时就会走这条），落回调试 shell |
| `…=FAIL(… e_machine 不是 EM_ARM)` | 交来了 arm64 镜像 | 换 arm32 产物 |
| `RESULT_STEP_handoff=EXEC(...)` 后 A9 init 无输出/重启 | 交棒成功但 A9 自己挂了 | 见 §5，pstore 回放会带上一轮尾巴 |

## 5. 本机已兜底、但仍需板上定论的三件事（别当已解决）

1. **SELinux**：交棒前已把 `precompiled_sepolicy` 喂进 `/sys/fs/selinux/load` 并兜 `enforce=0`
   （§2 第 5 步），但**前提是那份镜像里真有预编译策略**。若只有 `.cil`（本机与板上都编不出），
   `RESULT_STEP_selinux=NOPOLICY` 就是板上要盯的那一行。stock 线产过一份 v26 策略
   （394,417 B，见 `ANDROID9_Z1_HANDOFF_20261017.md` 台账），可以拿来喂。
2. **fstab**：已实现"从只读 system 里把 `fstab.z1` 投到可写 `/vendor/etc/fstab.<hw>`"，
   机型名取自 `/proc/cmdline`。但 A9 到底是记日志还是 `LOG(FATAL)` 对待缺 fstab，仍需板上证据
   —— 所以 `fstab=MISS` 这条必须出现在串口里才算数。
3. **cgroup/属性服务**：second-stage 自建 cgroup 与 `/dev/__properties__`，与 mainline 的
   cgroup v1 层次（`MEMCG/CGROUP_FREEZER/CPUSETS/RT_GROUP_SCHED` 本轮都已开）是否对得上，
   也是板上见分晓。

这三条正是交棒设计**故意保留调试 shell 落回**的原因：判定不过时串口链一点没少。

## 6. 现在离"可刷写的安卓镜像"还差什么

只差一份**真实的 arm32 A9 system.img**（本机既编不出也下不到，见 §1 的复测记录）。
拿到后本机一条命令自证 + 三步出全片：

```sh
python3 tools/z1/z1_a9_system_accept.py <system.img>                 # 只读验收
python3 tools/z1/z1_a9_mainline_system.py --system <system.img> --out out/a9sys   # 撤 stock 门控 + 投 device 层
tools/z1/z1_a9_flashpkg.sh --boot out/boot_mainline_a9p9_D1_1b.img \
        --system out/a9sys/system_mainline.img                        # 装配时自动跑验收闸（含 device 层）
```

交棒链已就位，boot 侧不再需要任何来自 AOSP 构建的产物。

## 7. 取料机制（本轮实测出来的，别再靠猜）

`download.lineageos.org` 只是 SPA 壳；**真入口是它的 JSON API 与 mirrorbits**：

```sh
# 1) 有哪些构建（返回 [] 就是官方已下架这个设备/分支）
curl -s https://download.lineageos.org/api/v2/devices/<codename>/builds
# 2) JSON 里每个文件带 url 与 filepath，url 形如
#    https://mirrorbits.lineageos.org/full/<device>/<date>/<file>.zip —— 这是**真下载口**
# 3) mirrorbits 会 302 到具体镜像（本轮拿到过 mirrors.ustc.edu.cn 与 mirror.freedif.org）
curl -sI https://mirrorbits.lineageos.org/full/sweet/20261015/<file>.zip | grep -i '^location'
```

实测边界（这是本轮"拿不到 A9 arm32 原料"的**精确**说法，不是笼统的不存在）：
- 现役 arm64 设备（sweet）在 API 里有构建、mirrorbits 能 302 —— 机制本身通；
- **LOS 官方已把 16.0 那批 arm32 设备下架**：`ham/find7/kccat6/lentislte/r5/m0` 的
  `builds` 全返 `[]`，mirrorbits 对 `16.0/ham/...` 返 **404**（真 404，不是 SPA 壳），
  USTC 镜像 `/lineageos/` 根下只剩 `exp/ full/ su/ tools/`，`full/ham/` 404 —— 官方源里就没有了；
- `androidfilehost.com`、`download.mokeedev.com`、`downloads.codefi.re` 在本机全部超时，
  `sourceforge.net` 403。非官方 16.0 包基本只活在这几处，所以本机取不到。
- `blob.lineageos.org` 是真能下文件的 LOS 主机（autoindex 里 `twrp/ heimdall/` 等，
  例：`downloads/twrp/twrp-3.2.3-20190202-ham.img` 12,175,360 B），但不放 ROM。

结论：**A9 arm32 的 system 原料必须由持镜像的那台机器给**（或换一台能连 AFA/XDA 的机器下）。
本机已把"拿到之后要做的事"全部工具化，见 §6。

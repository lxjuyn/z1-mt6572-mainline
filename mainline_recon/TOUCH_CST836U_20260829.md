# Z1 触摸控制器 CST836U 调研定案 — 2026-08-29 (浏览器联网 + 树内代码双源)

任务: 交接清单"键盘 keymap 补字符键/驱动移植"替代路线——Z1 触摸启动可行性。
结论速览: **CST836U 协议 = FocalTech FT6206 风格 8 位寄存器 @ I2C1 0x15;
树内现成驱动 = edt-ft5x06 (compatible "focaltech,ft6236", CONFIG 已 =m)。
本轮证据优先: 不启节点、不动 zImage, v13.4 ramdisk 带 i2cprobe 上板取证;
证据到手后加节点即可, 预计零/极小驱动工作量。**

## 一、证据链 (按可信度排序)

1. **原厂固件 (最强, 已有)**: `1/boot.img` 原厂内核含 Hynitron 驱动与固件串
   `HYN_CST836U_DWZN_MT6572_4.4_V1.0_20181106`; vendor 运行时 log:
   `hyn_ts: probe of 1-0015 failed with error -1` (I2C1 地址 0x15)。
   实体存在未证 (vendor 自己 probe 也失败), GPIO/供电/时序未证。
   (出处: I2C_TOUCH_CONTROLLER_AUDIT_20260717.md)
2. **EdgeTX 独立实现 (本轮新增, 联网)**: 开源遥控器固件 EdgeTX
   (github.com/EdgeTX/edgetx, `radio/src/targets/pl18/touch_driver.cpp` 与
   `boards/helloradio-h750/touch_driver.cpp`) 在真实硬件上驱动 CST836U:
   - 地址 `TOUCH_CST836U_I2C_ADDRESS 0x15` (与 Z1 vendor 探测地址一致!)
   - **8 位寄存器 / FT6206 风格触点布局**:
     0x02 = 触点数 (FT6206 TD_STAT 同位), 0x03 = P1_XH 起 4 字节
     XH/XL/YH/YL, 12 位坐标, event 在 XH bit7:6, contact=0x02
   - 身份寄存器: 0xa6/0xa7 FW 版本, 0xa8 模块版本, 0xa9 项目名,
     0xaa/0xab 芯片类型 —— 与 FocalTech 寄存器图 (FIRMID 0xa6,
     FOCALTECH_ID 0xa8) 对齐
   - 复位时序: RST 低 10ms → 高, 等 300ms; IRQ 下降沿
   (grep.app 全网检索 "CST836U" 命中 EdgeTX 11 处; hynitron_cst9217 等其它
   vendor 移植均为别的大屏芯片, 不涉及 836U 协议)
3. **树内驱动核对 (本轮新增)**:
   - `drivers/input/touchscreen/edt-ft5x06.c` of_match **含
     `focaltech,ft6236`** (edt_ft6236_data, L1531); 读触点走 regmap,
     FT6236 数据布局即 0x02/0x03 起同款 → **协议匹配**
   - `hynitron_cstxxx.c` = CST3XX 协议 (16/24 位寄存器,
     chkcode 高 16 位须 0xcaca0000), of_match 仅 "hynitron,cst340" → 不匹配
   - `hynitron-cst816x.c` = CST816S 协议 (0x01 起单点结构), 仅
     "hynitron,cst816s" → 布局不同, 不匹配
   - `.config`: `CONFIG_TOUCHSCREEN_EDT_FT5X06=m` **已开** (树内有编好的
     edt-ft5x06.ko), vermagic 7.0.0-rc7-z1+ 兼容
4. **GT911 维持排除** (审计定案: cci72_we_jb3 参考板猜测不越原厂证据)。

## 二、本轮执行 (决策树"证据优先"分支)

- 不开任何触摸 CONFIG、不动 zImage (保住"与已验证版逐字节一致"链)。
- `tools/i2cprobe` 扩展 (备份 `bridge_backups/i2cprobe.c_orig_*.bak`):
  - `i2cprobe <bus> <addr>...` 窄地址模式 (审计纪律: 只探目标地址,
    禁盲扫)
  - `i2cprobe <bus> dump <addr> <reg> <len>` 寄存器只读转储
    (写 1 字节子地址后读, 不写任何数据字节)
  - ARM 静态重编 341,188 B, 已入 `out/ramdisk_v13_4_acm.gz` 的 sbin/。
- z1.dts GT911 占位注释更新为上述证据链 (commit 409fb7313)。

## 三、上板取证脚本 (v13.4 刷入后, 串口或 ttyGS0 shell)

```
i2cprobe /dev/i2c-1 0x15            # 存在性 (quick ACK / 单字节读)
i2cprobe /dev/i2c-1 dump 0x15 0xa6 6   # [FW_L FW_H MOD PROJ CHIP_H CHIP_L]
i2cprobe /dev/i2c-1 dump 0x15 0x02 8   # TD_STAT + 首点坐标 (无触摸也安全)
```
判读: 0xa6 起读出非全 0x00/0xFF 且 0xaa/0xab 有像样芯片号 → CST836U 在位。
4. 之后的节点 (下轮, 需 GPIO 证据配合):
   `edt-ft5x06` 节点: compatible="focaltech,ft6236", reg=<0x15>,
   reset/irq-gpios 仍缺 Z1 实证 (128/129 是参考板值, 未经证不可盲用——
   vendor log 亦未给 GPIO), 供电可挂 mt6323_vgp1/vio18 (TBC)。
   若实机 GPIO 取证无门 (无原理图), 备选: 老板 NCI/CBA 面向 "hyn_ts"
   vendor 驱动源反查 GPIO 配置 (需用户提供或继续搜 vendor 树)。

## 四、风险与边界

- vendor probe 失败 (-1) 意味芯片可能根本不在位/未上电 —— 取证前别预设存在。
- i2cprobe 的 quick/单字节读对 0x15 若 NACK 无副作用; dump 只读寄存器,
  CST836U 寄存器图无"读副作用"记录, EdgeTX 同款用法在真机常态运行。
- 审计纪律不破: 未做全总线扫描 (全扫模式仍在, 但仅限人工显式调用)。

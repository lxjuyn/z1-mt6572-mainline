# Z1 (MT6572) 主机侧 ADB 连接规划 — 2026-08-15

> 只读 + 联网调研产物。主机 = Linux Mint/Ubuntu 系 (当前是 Ubuntu noble 内核 6.17)。设备 = Z1 (MT6572) mainline 内核 + busybox initramfs。
> 本文件只覆盖**主机侧**准备与连接步骤；设备侧缺口做如实评估（§4），供后续路A/B决策。

---

## 0. 一句话结论

- **主机侧已基本就绪**：`adb` 已装 (34.0.4-debian)，udev 已有 MTK (0e8d) 通配规则。只需补一个「adbusers 组不存在」的权限兜底（§5.2），无需安装任何新包。
- **设备侧 ADB 未实现**：当前 mainline 内核**没有 adb function**（`CONFIG_USB_CONFIGFS=n`、树内无 `f_adb.c`、无 `g_android`），gadget 走的是 `g_serial` (CDC-ACM `/dev/ttyGS0`)；当前 boot 用的 initramfs（`out/forensic/linux/rd`）**没有 adbd、没有 /system/bin/sh、没有 Android property service**。因此 **现状 `adb devices` 看不到 Z1**——它枚举为 CDC-ACM 串口（class 0x02），不是 adb interface（class 0xFF/0x42/0x01）。
- 要让 USB ADB 通，设备侧需要：① 内核移植 AOSP `f_adb.c` + 开 `CONFIG_USB_CONFIGFS=y`；② 跑一个 adbd（原厂静态 adbd 可复用，但依赖 Android init/property 服务，见 §4.2）。这是后续任务，主机侧先备好。

## 2. 联网调研结论

### 2.1 安装方式（advisory，本机已装无需执行）
- Mint/Ubuntu/Debian：`sudo apt install android-tools-adb`（或 `android-tools`），对应 `/usr/lib/android-sdk/platform-tools/adb`。
- 要最新版可下 Google 官方 platform-tools zip（`https://developer.android.com/tools/releases/platform-tools`），解压即用，无依赖。distro 包 34.0.4 对本任务足够。

### 2.2 "no permissions" / "not authorized" 两种报错的 udev 处理（社区共识）
- **no permissions**：/dev/bus/usb 节点权限不够。修法：
  ```
  SUBSYSTEM=="usb", ATTR{idVendor}=="<VID>", MODE="0666", GROUP="plugdev"
  ```
  写入 `/etc/udev/rules.d/99-android.rules` 后：
  ```
  sudo udevadm control --reload-rules && sudo udevadm trigger
  # 或重启 / 重新插拔
  ```
  兜底可 `sudo adb kill-server && sudo adb devices`（root 跑 server）临时验证。
- **unauthorized**（不是权限问题）：设备侧 RSA 握手要求主机确认授权。有屏设备弹框点"允许"；无屏设备（Z1 场景）两种做法：
  1. 设备侧 `ro.adb.secure=0`（Z1 原厂 default.prop 就是这个值 → 本场景天然免授权）；
  2. 把主机 `~/.android/adbkey.pub` 推到设备 `data/misc/adb/adb_keys`。
- 注意：规则只影响**节点权限**；adb **能否识别为 adb 设备**由 interface-class 决定（见 §3），udev 管不到这层。

## 3. Z1 设备枚举信息（权威，来自原厂固件解包，非猜测）

Z1 原厂 3.4.67 固件 `out/boot_extracted/rd/` 解包事实：

| 项 | 值 | 出处 |
|---|---|---|
| USB VID | `0e8d` (MediaTek Inc.) | `init.usb.rc` 写 `$sys.usb.vid`；MTK 惯例 |
| ADB-only 模式 PID | **`0C01`** | `init.usb.rc` `on property:sys.usb.config=adb` |
| ADB+ACM 复合 PID | **`200E`** | `init.usb.rc` `on property:sys.usb.config=adb,acm`（`f_acm/instances 1`） |
| 认证 | `ro.adb.secure=0` → **无 RSA 认证**，主机插上直接 "device" | `default.prop` |
| 调试位 | `ro.secure=1`（init 不降权），`ro.debuggable` 由 adbd 读 | `default.prop` / adbd strings |
| 默认 USB 配置 | `persist.sys.usb.config=mass_storage`（Android 里切到 adb 才出 adb） | `default.prop` |
| adbd 路径/形态 | `/sbin/adbd`，**静态链接** ARM EABI5, stripped, 202968B, md5 `05845e16...`（三份解包一致） | `out/{boot_extracted,forensic/rd_stock_extract,forensic/live}/rd/sbin/adbd` |
| adbd 依赖 | strings 含 `ro.adb.secure / ro.debuggable / service.adb.tcp.port / persist.adb.tcp.port`；shell **硬编码 `/system/bin/sh`** | adbd strings |
| adbd 启动 | `service adbd /sbin/adbd`，class core，socket adbd，disabled，靠 `sys.usb.config` 属性触发 | `init.rc` |

MTK 家族 PID 惯例（联网佐证）：`0e8d:2000` = MT65xx Preloader，`0e8d:2001` = SP_DA，`0e8d:0003` = 旧 MT6227 phone / 3.4 时代常见 MTK 调试端口。Z1 出厂 `adb` 模式用 0C01、`adb,acm` 用 200E。

## 4. 主机 `adb devices` 看到 Z1 需要什么（评估）

### 4.1 主机侧检测机制（为什么 VID/PID 不是关键）
现代 adb（1.0.32+，含本机 34.0.4）用 libusb **扫描 USB 接口描述符**：任一 interface 为
`bInterfaceClass=0xFF, bInterfaceSubClass=0x42, bInterfaceProtocol=0x01`（即 adb 传输层，字符串 `ff4201`）
即识别为 ADB 设备并加入 `adb devices` 列表。因此：
- **不要求固定 VID/PID**，不依赖 `adb_usb.ini`。Z1 用 0C01/200E 或任意自定 PID 都可，只要 interface-class 对。
- 识别到手后还需要 **设备侧 adbd 应答 AUTH/CNXN 握手**：
  - 无应答 → 设备显示 `offline`；
  - 有应答但主机未授权（RSA）→ `unauthorized`；
  - 握手完成 → `device`（可 `adb shell`）。
- Z1 无屏，**必须免认证**（`ro.adb.secure=0`，原厂即如此），否则只能靠手动推公钥，而当前 initramfs 没有 `/data/misc/adb` 可写点。

### 4.2 设备侧缺口（当前阻塞点，如实评估）
| 需求 | 现状 | 差距 |
|---|---|---|
| 内核 gadget 有 adb function | `CONFIG_USB_CONFIGFS=n`，`drivers/usb/gadget/function/` **无 f_adb.c**，无 g_android | **缺**。需移植 AOSP `f_adb.c`（~350 行 + Kconfig/Makefile），开 `CONFIG_USB_CONFIGFS=y`，initramfs 里 configfs 绑定 MUSB UDC |
| 当前枚举形态 | MUSB `g_serial` (CDC-ACM `/dev/ttyGS0`)，interface class 0x02 | 不是 adb；`adb devices` 不会认 |
| adbd 进程 | mainline initramfs **无 adbd** | 原厂静态 adbd 可复用，但依赖 Android property service + `/system/bin/sh`（busybox init 都没有）→ 直接跑会挂。需 cross 编现代独立 adbd（shell 指向 `/bin/sh`、可关认证）或先起 Android init 栈 |
| TCP ADB 替代路径 | 无网络接口（WiFi CONNSYS 模块编出未上板验证，无 eth） | `adb connect ip:5555` 暂时走不通，先靠 USB |

**结论：主机侧准备到此为止即可；设备侧 f_adb+adbd 是独立工作包（建议 route A 之后做）。**

### 4.3 主机能做的预验证（即使设备侧没 adb 也能验证链路）
- 插 Z1（内核起来后，避开 preloader LineState 坑），`lsusb` 应见 `0e8d:0c01`（若将来设备侧上了 f_adb）或当前 `0525:a4a7`（g_serial，NetChip gadget serial）。
- 当前 g_serial 阶段可验证**主机 USB 链路**：`dmesg` 见 CDC-ACM 枚举，`/dev/ttyACM*` 出现——说明 musb 外设通路 OK，后续 f_adb 就绪后主机侧零改动。

## 5. 主机侧准备清单（具体命令）

### 5.1 adb —— 已装，无需操作
```
adb version   # 34.0.4-debian ✅
```
若日后要升官方版：下载 platform-tools zip 解压，或 `sudo apt install android-tools-adb`。

### 5.2 udev —— 需要一步兜底（推荐方案 B，双保险）
现状唯一风险：`50-android.rules` 通用 ff420? 规则把节点设成 `GROUP=adbusers`（组不存在 → root:root 0660），会盖过 `20-mtk.rules` 的 0666。修法二选一（**建议都做**）：

**A. 建 adbusers 组并把自己加进去**（让官方通用规则生效）：
```
sudo groupadd adbusers
sudo usermod -aG adbusers $USER   # 需重新登录才生效
```

**B. 新增 Z1 专用规则**（更直接，覆盖 0C01/200E，MODE 0666 + plugdev，文件号 99 保证最后生效）：
```
# /etc/udev/rules.d/99-z1-adb.rules
# Z1 (MT6572) ADB modes: adb-only=0C01, adb+acm=200E (stock init.usb.rc)
SUBSYSTEM=="usb", ATTR{idVendor}=="0e8d", ATTR{idProduct}=="0c01", MODE="0666", GROUP="plugdev", SYMLINK+="z1-adb"
SUBSYSTEM=="usb", ATTR{idVendor}=="0e8d", ATTR{idProduct}=="200e", MODE="0666", GROUP="plugdev", SYMLINK+="z1-adb-acm"
```
（`20-mtk.rules` 已按 VID 全量覆盖 0e8d→0666，99 规则主要防 50-android 的 adbusers 覆盖。）

**应用规则：**
```
sudo udevadm control --reload-rules
sudo udevadm trigger
# 或直接重新插拔 Z1 USB
```
验证：`ls -l /dev/bus/usb/*/* | grep -i ...` 出现 `crw-rw-rw-`（0666）。

### 5.3 验证链路（设备侧 f_adb 就绪前可先验 USB 通路）
- 内核起来后插 Z1 USB → `dmesg | grep -i usb` 应见枚举；`lsusb` 见 MediaTek。
- 设备侧 adb 就绪后：`adb devices -l` 应出现类似 `XXXXXXXXXXXX device usb:1-x`（serial 由 adbd 上报）。

## 6. 连接步骤（设备侧 ADB 就绪后）

```
# 0) 前提：Z1 已刷含 f_adb 的 mainline 内核 + 已跑 adbd 的 initramfs（见 §4.2 设备侧工作包）
# 1) 正常开机（拔 USB 开机），内核完全起来后【再插 USB】（避开 preloader LineState download 坑，项目既有纪律）
# 2) 主机：确保本用户可访问节点
sudo udevadm control --reload-rules && sudo udevadm trigger
# 3) 重启 adb server（干净状态）
adb kill-server; adb start-server
# 4) 确认枚举
lsusb                # 期望 0e8d:0c01 (adb) 或 0e8d:200e (adb+acm)
adb devices -l       # 期望: <serial> device usb:1-x   (ro.adb.secure=0 → 直接 device, 不会 unauthorized)
# 5) 交互
adb shell            # busybox sh (设备侧 shell 路径待 f_adb+adbd 工作包定)
adb root             # 若 ro.secure 需提权(取决于 adbd 行为)
```

**状态字排错**：
| `adb devices` 显示 | 含义 | 处理 |
|---|---|---|
| 空 | 没枚举 / 节点权限不行 / 设备不是 adb interface | 看 lsusb+dmesg；若枚举为 CDC-ACM → 设备侧 f_adb 未上 |
| `no permissions` | udev 节点权限 | 做 §5.2 并 reload + 重插 |
| `offline` | adbd 在跑但握手没完成（旧 adbd 与 adb 34 协议差异 / 版本不匹配） | 确认 adbd 起来、试 `adb kill-server` 重启；极端换官方 platform-tools |
| `unauthorized` | RSA 认证弹窗无屏可点 | 设备侧 `ro.adb.secure=0` 或推 `~/.android/adbkey.pub` 到设备 adb_keys |

## 7. 风险与注意

1. **preloader LineState 坑**：Z1 接电脑 USB 会干扰 boot（进 download 循环）——刷写才插、正常开机拔掉；ADB 交互是**内核起来后再插**，两态分开，与项目既有纪律一致。
2. **旧 adbd vs 新 host adb**：原厂静态 adbd 是 3.4.67 时代（Android ~4.x）产物，与 adb 34.0.4 的传输协议向后兼容概率高但未验证；若 `offline`，优先换官方 platform-tools 再试，其次换现代 standalone adbd。
3. **adbd 依赖**：原厂 adbd 静态无 libc 依赖，但 strings 证实依赖 property service + `/system/bin/sh`；在 busybox initramfs 里直接跑会挂（`property_get` 连不上 `/dev/socket/property_service`）。设备侧工作包要么配套最小 property 实现，要么 cross 编独立 adbd。
4. **本机无 adbusers 组**是唯一主机侧权限隐患，§5.2 必须做，否则设备侧 f_adb 好了也会被 50-android.rules 挡成 root:root。
5. **adb TCP 替代路径暂不可行**：mainline 下 Z1 无网络接口（WiFi CONNSYS .ko 已编出但未上板验证、无 eth），`adb connect ip:5555` 需先解决网络；USB ADB 是当前唯一现实路径。

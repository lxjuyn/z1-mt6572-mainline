# v13.1: initrd 截断根因定案 + 修复 + 上板验证通过 (2026-08-26 凌晨)

> 状态: **v13 启动失败已定案并修复** (`read error` / error -26 连锁消失)。
> 新卡点已转移到 mtk-msdc eMMC CMD1 硬挂起 (见本节末尾)。

## 根因定案 (含对交接文档三假设的修正)
- **根因**: `fork_linux/arch/arm/boot/dts/mediatek/mt6572-z1.dts` chosen 节点硬编码
  `linux,initrd-end = <0x841e2810>` 是**旧 ramdisk 的过期值**, 把内核可见 initrd 窗口截短到
  929,792 B (即日志里的 `Freeing initrd memory: 908K`), 而 v13 ramdisk payload 为 **1,068,865 B**
  → 合法 gzip 流中途断粮 → `read error` → rootfs 空壳 → `error -26` 连锁。
- **交接文档"剥头补丁未执行"假设证伪**: Z1 原厂 LK 载入 ramdisk 时**已自行剥掉 512B MTK 头**,
  把裸 gzip 拷到 0x84100000 (LK 日志 `ramdisk @ 0x84100000 (1068865)` 为证),
  内核拿到的数据根本不含 MTK 头 → `init/initramfs.c` 剥头补丁的 magic 检测**必然 0 命中**。
  交接文档方案1 (主机端剥头重打) 单独执行**无法修复**。
- 三假设逐一修正:
  - **A (解包路径绕过补丁)**: 不成立/无关 —— 补丁本就不需要命中, LK 已代劳剥头。
  - **B (LK 载入截断)**: 方向对一半 —— 截断确实存在, 但不在 LK, 而在 dts `linux,initrd-end`
    给内核的窗口边界; LK 载入本身完整 (1068865 B 无缺)。
  - **C (pr_info 被 loglevel 吞)**: 证伪 —— 0 命中是条件不满足, 不是打印被吞。
- **纪律固化**: dts 的 `linux,initrd-end` 必须恒等于 `0x84100000 + ramdisk payload 字节数`,
  每次换/重压 ramdisk 必须重算 (此纪律已写入 dts 注释)。`tools/z1_make_bootimg.sh`
  默认 cmdline (ttyS0,115200) 仍禁用。

## v13.2a1 (2026-08-27) — cmdline 修正: ttyMT0 → ttyS0

> ⚠️ 2026-08-29 W1 定案推翻本节结论：本启动链 LK 不转发 boot 头 --cmdline，仅改头 cmdline 无效；console 选择已移入 dts chosen bootargs（见 AGENTS.md、REVIEW_v13_3b_CORRECTNESS_20260829.md、fork_linux 409fb7313）

### 背景与根因

(v13.1 时代的 mtk-msdc CMD1 硬挂起已在 v13.2a 修复), 但 userspace 输出全进了

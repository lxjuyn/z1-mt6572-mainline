## 三、S6 与 Z1 关键差异

### 可直接复用（占大头）
eMMC（mmc0）、UART、USB gadget + u2phy0、pwrap/MT6323 PMIC、四路稳压器 always-on（vemc/vmc/vmch/vusb 防重启循环）、CONN carveout 上移 0xbe000000、CONNSYS 外编栈 DT 节点（btif/connectivity/wifi）、audsys+sound、电池节点、appended-dtb 打包流程、6MB 分区纪律——全部从 Z1 原样继承。ramdisk 复用 Z1 的（1,069,377 B 的 v11 版）。

### 需要新做 / 重新验证

| 外设 | Z1 | S6 | 影响 |
|---|---|---|---|
| 屏幕 | DSI 面板（st7785m），simple-framebuffer LK handoff 出图 | **MCU 并口屏**（gc9307/nv3029s/st7789v），mainline 无驱动。**已定案：simple-framebuffer 原理性不可行**（MCU 屏自带 GRAM、一次性 burst 写入，LK 退出后无持续 DMA 刷新的 DRAM 表面） | **最大新工作量**：须移植厂商 LCM 驱动走 MCU/DBI 总线；dts 的 framebuffer0 节点只是未验证占位，勿在其上调参 |
| 触摸 | Goodix GT911（i2c0，disabled 占位） | **Focaltech FTS**（I2C）；首启故意不建节点，地址/IRQ/wake/reset GPIO 均未捕获 | 需 I2C1 扫描或厂商内核证据后加节点 |
| 按键 | PMIC 电源键 + 8x9 键盘矩阵 | **仅电源键**，无矩阵；home 键 disabled | 更简单 |
| I2C | i2c0 | i2c1（400kHz，引脚已 mux 好，待触摸节点） | — |
| 摄像头 | 无 | SP2519_YUV（明确暂不管） | — |
| sound 节点 | disabled | 已置 "okay"（依赖 pwrap write-deny 解除等前提） | — |
| bootargs | 仅 ttyMT0 | 额外 `ttyACM0,921600` 兜底 | — |
| PMIC_EINT / eMMC 引脚 | Z1 实测验证 | **均"照抄 Z1、TBC"**，未经原理图核实 | 首启异常优先怀疑 |

## 四、已知坑清单

1. **initrd-end 同款过期硬编码（已确认）**：`mt6572-s6.dts` L66-67 仍是
   `linux,initrd-start=0x84100000 / linux,initrd-end=0x841e2810`。这正是 Z1 在
   `47fd7e872`（v13.1, 08-26）定案修复的过期值（截断 initrd 窗口 → gzip read error / error -26）。
   Z1 已改 `0x84204f41`（对应 1,068,865 B ramdisk），**S6 没同步**。
   注意：S6 若仍复用 1,069,377 B 的 ramdisk，正确 end 应为
   `0x84100000 + 1069377 = 0x84205141`，须按实际打包的 ramdisk 长度重算，不能直接抄 Z1 的值。
2. **现有三个 s6 镜像全部过期**：v1/v2/v3 均为 08-23 打包，不含 08-24 的
   ttyACM0 兜底、WDT 安全网，也不含后续 msdc CMD1 相关修复
   （`8cec21a62`/`87f3f59b0` 只动了 z1 dts 语境）。重新上板必须重打。
3. **无串口可见性**：上板卡 logo、零输出，且不知 S6 UART 测试点在哪。
   ttyACM0 console 兜底正是为此——首启插 USB 观察是否枚举出 ACM 口
   （但须当心 AGENTS.md 坑 3：插 USB 可能触发 preloader 下载模式/重启循环，需实测平衡）。
4. **显示路线已被研究否决**：不要在 simple-framebuffer 上继续耗（勿调几何参数），
   s6.dts L11-28、L69-77 注释已明确；出路是移植厂商
   `gc9307_mcu_6572_s6_24_hsd`/`nv3029s_mcu_6572`/`st7789v_mcu_6572` LCM 驱动。
5. **eMMC/PMIC 假设未验证**：mmc0 引脚（照抄 Z1 的 6mA 配置）与
   PMIC_EINT=GPIO7 均标注 "TBC on S6 schematic"；且 Z1 当前自身卡在
   mtk-msdc CMD1 硬挂起（v13.2a/b 在途），同款 msdc + 同代 LK handoff
   对 S6 大概率同样存在。

## 六、建议适配路线

1. **前置（硬件）**：定位 S6 UART 测试点（V13_BOOTFAIL_HANDOFF §四-5 遗留项），否则全程盲调。备选：利用已加的 ttyACM0 兜底，首插 USB 观察 ACM 枚举。
2. **同步 Z1 战果**：首要**按实际 ramdisk 长度重算并修掉 `linux,initrd-end`**；随后视 Z1 对 msdc CMD1 挂起的定案结果，决定是否带入 `8cec21a62` msdc 修复、`87f3f59b0` mmc0 隔离策略。
3. **重打镜像**：从当前 HEAD 重编后打 s6_v4（现有 v1~v3 全部作废），沿用 `cat zImage+dtb → mkbootimg --mtk 1` 流程，检查 ≤6MB。
4. **首启目标**：串口/ACM 出 earlycon 输出 → initrd 解包 → /init 跑通；显示、触摸、按键、摄像头全部后置。
5. **中期新工作量**：Focaltech FTS 触摸（先 I2C1 扫描取证）→ MCU LCM 显示驱动移植（最大单项；工作区内目前未找到这些厂商源文件，需向用户确认来源）。
6. **优先级**：Z1 尚未跑通 userspace-on-eMMC，建议 S6 保持"编译就绪、低优先级"，待 Z1 v13.x 通关后再集中投入；两板可互为验证（尤其 msdc/PMIC 假设）。

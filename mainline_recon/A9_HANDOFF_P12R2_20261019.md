## 4. 复现出货件（一条命令）

```bash
cd /home/lxj/claude/6572
# 前置：a9_wt 已 checkout（不改动源码）、zImage/dtb 已按 mt6572-z1_a9_defconfig 编出、
#       out/ramdisk_a9p9.gz 与 out/z1a9_r2/system.raw.img（sha 必须 == b6daba2417dedc33…）在位
BOOT=/home/lxj/claude/6572/out/A9_final_p12/boot_mainline_a9_final_1b.img \
DIR=/home/lxj/claude/6572/out/A9_flashpkg_p12_r2 \

```
链上依次是 step0 `devcheck` → sha 硬闸 → 未改造验收（此时 REJECT 属预期：缺 ueventd + HIDL disabled）→ adapter → flashpkg（内含 `--expect-adapted` 验收）→ 独立复核。**每一步的退出码都被显式接住**，任何一步非零就 `exit 3`，不会"半条链跑完还报绿"。
boot 单独重打：`A9_RAMDISK=out/ramdisk_a9p9.gz bash a9_wt/tools/z1/z1_a9_p2.sh pack <1b|4b> <out.img>`。
⚠ `pack` 会**就地改 dts**，而"最后一次 pack 决定源码树状态"——打完 4b 必须补打一次 1b 收尾（本轮就是这么把 `a9_wt` 留干净了）。

## 5. 本轮修掉的洞（下个 agent 最可能重犯的两类）

**共性教训：`debugfs` / `mkbootimg` / 校验器的退出码都不说谎，说谎的是"你没看它的 stdout"。凡是"绿了"的交付物，必须做负测试。**

1. **i_mode 类型位被抹平（作废了 P10/P11 两版包）**。`set_inode_field` 按 `strtoul(base 0)` 解析：裸 `'0755'` 是八进制 493 → **整个 i_mode 被覆盖成不含 S_IFREG** → inode `Type: bad type`，而权限位、`debugfs cat` 读回、sha 全部正常，**内核却打不开这个文件**；想补类型位写 `'100755'` 又被当**十进制** `>65535` 拒绝，错误只在 stdout、**退出码仍为 0** → 补权限静默空转。修法：mode 一律 `0o100000|perm` 写成 `'0100xxx'`，写后调 `assert_regular()` 解析 `stat` 文本断言 `regular`。新闸 `file_type`。
   - 旁证曾被误读：e2fsck 那句 `Inode 1654/1655… 的 i_blocks 应为 0`（rc=4）此前被归类成"原厂打包器的记账瑕疵，可直接刷"，**其实是类型位丢失的直接信号**。现在 `i_blocks` 已进结构性损坏正则。
2. **`debugfs write` 撞已存在路径静默失败**：r2 的 system 本来就自带 `xt_{quota2,IDLETIMER}.ko`，第一次跑 r2 路线时模块没被覆盖，adapter 在 sha 读回处 ABORT(rc=3)——**但脚本把 adapter 管进 `tail`，rc 被管道吃掉**，于是半改造镜像进了包还拿到 ACCEPT。修法：dest 已存在先 `rm` 再写；`net_modules` 闸从"只验 ELF magic"**升级为与 `modules.json` 比 sha**；链上每步 `rc=$?` 显式接住。坏件留证 `out/A9_flashpkg_p12_r2.BAD_halfadapt/`。
   - 覆盖依据如实记：r2 原装那两个 .ko 的 vermagic **也是 `7.0.0-rc7-z1+`**，覆盖不是为了纠 vermagic，而是为了与本轮实际出货的 zImage **同树同产物**。
3. **`z1_defconfig` 缺 97 项 A9 符号**（整条 legacy netfilter 链、`SELINUX_DEVELOP`、`MEDIATEK_WATCHDOG`、`IP_NF_*` 表…）。任何人 `make z1_defconfig` 就得到一个 A9 起不来的内核 → 已用 `savedefconfig` 反向生成 `mt6572-z1_a9_defconfig`，往返与基准 `.config` **6683 行逐字节零差异**。**bring-up 基线仍用 `z1_defconfig`，A9 一律用 a9 那份。**
4. **`z1_a9_ramdisk_accept.py` 自我矛盾**：它 REJECT P9 ramdisk，只因 `sbin/z1_a9_handoff.sh` 的**注释与 DIAG 文案**里带 `/z1_stock_kernel` 字样（它在说明"已撤销"），而同一脚本 L2 形态 B 又强制要求交棒件在位。现按同文件里 `/dev/ion` 已有的 `sbin/` 豁免先例处理，并保留 WARN。**负测试**：往 `/init` 真塞 `ro.z1.stock_kernel=1` 仍 REJECT。
5. **盘上那份 r2 system 是碎片拼的赝品**（已重取，旧件留证 `system.raw.img.FAKE_fragment`）：sha `fa80c785…` ≠ release 的 `b6daba24…`、xattr 块损坏、`dl_sys.log` 记 `http=404`、目录里曾有 `.g.0`/`.g.29` 碎片，**尺寸刚好凑满分区所以躲过了尺寸闸**。取件通路：`gh-proxy.com` 对**该仓** `releases/download/` 口回 Not Found，要用 `api.github.com` 的 asset 端点（`Accept: application/octet-stream`，凭据经 stdin 喂给 `curl -K -`，勿进 argv）。
6. `z1_a9_devcheck.sh` 原先只靠"人记得手动跑"，一条 FAIL（`rootdir/.gitignore 被 COPY 引用`）就是这样被绕过出过一次片 → 现已接成两条链的 step0。

**作废、勿刷、勿当依据**：`out/A9_flashpkg_p10_gsi_preinit/`、`out/A9_flashpkg_p11_android/`（洞 1）、`out/A9_flashpkg_p12_r2.BAD_halfadapt/`（洞 2）。

## 7. 剩下真正的工作（按优先级）

1. **拿一次串口真值**（阻塞一切后续判断）。判据与已知三条见 §6。若 0 输出，先查"appended dtb 有没有 cat 到 zImage 末尾"（本项目最大坑，`AGENTS.md` §5 坑 1），**别先怀疑 earlycon 或 WDT**。
2. **SELinux 收紧**：需要一个**真的 A9 secilc 产物**（`precompiled_sepolicy`，magic `0x45524F53`、version 落在本树 `security/selinux/include/security.h` 的区间内）。来源要么在持 LOS16 源树的机器上产，要么从同源 release 找。`z1_a9_mainline_system.py` 已有魔数/版本闸门，投错会被拒。
3. **显示二阶段**：本轮走 fbdev/`/dev/fb` + `simple-framebuffer`（dts chosen `framebuffer0@bfd00000`，见 `out/PACKAGE_NOTE_s6_v6.md` §八 的拆雷记录）；lima+GBM 后置，那时才需要 `ION→dma_heap` 垫片（本仓 gralloc 走 ashmem+`/dev/fb`，第一阶段不需要）。
4. **触摸**：CST836U=FT6206 协议@0x15，候选 `edt-ft5x06`；先用 ramdisk 内 `sbin/i2cprobe` 上板取证再加节点（`mainline_recon/TOUCH_CST836U_20260829.md`）。
5. 若板上确认 WiFi/BT：`wlan_mt6620.ko` 等 7 个外编 .ko 是"能编出"级，平台层 GPIO/EINT/RTC 全是 no-op 桩，真跑要重写成 mainline DT + gpio_desc。

## 8. 禁做清单（红线，违反会烧掉一次上板或毁掉回滚路）

- 不 `make z1_defconfig` 出 A9 片；A9 只用 `make mt6572-z1_a9_defconfig`。
- **绝不在 make 命令行设 `LOCALVERSION=`**（会消掉 vermagic 尾部 `+`，使全部 .ko 失配）；vermagic 固定 `7.0.0-rc7-z1+`。
- 不改 `fork_linux`（`main`）的工作树去跑 A9；A9 只在 `a9_wt`。
- 不用 mkbootimg 的 `--dt` 代替 `cat zImage dtb`（appended-dtb 是本移植最大坑）。
- 别指望 boot.img 头的 `--cmdline`：本启动链的 LK **不转发**它，引导参数一律写进 dts `chosen/bootargs` 并重编 dtb。
- 不往镜像根新建 `/system/` 目录（交棒脚本见 `$SYSROOT/system` 会 `mount -o bind` 下移一层，会错位）。
- 不格式化 `usrdata`；不擅自扩 scatter 的 `is_download`；原厂 scatter 有 10 个分区默认开启下载、其中 preloader 的 `file_name` 是空值、`uboot` 里是唯一原厂 LK —— **一键 Download 会自断回滚路**。
- 不新建仓库/分支；不 `git add -A` 一把梭；**push 前扫隐私**（密钥之外还含 MAC/SSID/邮箱/手机号/序列号/日志隐性数据）。所有仓都是 public。
- 改动前先带时间戳备份到 `bridge_backups/`，产物归档到 `bridge_backups/products/`。

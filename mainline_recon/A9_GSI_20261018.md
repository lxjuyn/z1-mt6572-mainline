# 真 A9 arm32 system 到手（phhusson GSI v123）与本轮修掉的四个错（2026-10-18）

## 1. 结论先说

本机**第一次拿到了一份真实的 Android 9 / API 28 / armeabi-v7a 系统镜像**，并把它改造成
可直接刷进 Z1 `android`(p4) 分区的形态：


## 2. 唯一剩下的缺口：A9 自己的 PID1（两个二进制）

A-only 的 GSI **刻意不含** `/system/bin/init` 与 `/system/bin/ueventd`（它假定设备的 boot ramdisk
提供 first-stage）。全镜像遍历确认：`find` 只找到 `/etc/init/*.rc` 这类脚本，没有任何 `init` ELF。
所以这份 system 现在刷上去，交棒链会停在：

```
[a9hand] RESULT_STEP_handoff=FAIL(没找到可执行的 A9 init：查过 /system/bin/init、…、/sbin/a9_init)
```
这不是 system 内容的问题，而是**差两个文件**。本机已把它做成普通输入件：

```
android9/mainline/rootdir/bin/init          # EM_ARM 的 A9 init
android9/mainline/rootdir/bin/ueventd       # 同上
```
放进去后重跑 `z1_a9_mainline_system.py`，两个二进制就随 device 层一起进 `<P>/bin`，
`z1_a9_system_accept.py` 与 `z1_a9_flashpkg.sh` 的闸会放行，包即为最终安卓成品。
兜底通道也已就位：交棒脚本在 `/system/bin/init` 不存在但 ramdisk 里有 `/sbin/a9_init` 时，
临时把 `/system` 转 rw 种入 init/ueventd、sync、立即回 ro，并打 `RESULT_STEP_seed=OK|FAIL`。
来源任选：任意一份 arm32 Android 9（LOS 16.0 / AOSP 9 `aosp_arm`）的 system.img 里取即可。
取料通道见 `A9_SYSTEM_ADAPT_20261018.md` §10（分片 sha 逐片校验）。

## 3. 本轮被真镜像抓出来的四个错（都是"只在夹具上测过"的分支）

1. **仓里的 sparse 解析是错的，且对任何真 sparse 镜像都不成立。** 原实现把 magic 写成
   `0x3AFF26AF`、头部按 9 个 `u32` 解（真实是 `0xED26FF3A` + `u32 magic,u16 major,u16 minor,
   u16 file_hdr_sz,u16 chunk_hdr_sz,u32 blk_sz,u32 total_blks,u32 total_chunks,u32 crc` = 28 B）。
   新模块 `tools/z1/z1_a9_sparse2raw.py` 按真布局实现，并逐 chunk 校验 `total_sz` 算术与块数合计。
2. **`DONT_CARE` 不推进输出偏移** → 第一个空洞之后的所有 RAW 全写到错位置，根 inode 被写坏；
   我随后 `e2fsck -fy` 一把，把 `/system` 直接清成空壳（只剩 916 MB 的 lost+found）。
   这解释了"为什么必须先 `e2fsck -fn` 看报告、再看 `debugfs ls`，不能信 rc"。修好后
   `dumpe2fs` 认块、`e2fsck -fn` rc=0、`debugfs` 能列 2859 条路径。
3. **`image_write` 假设了 `/system/etc` 这种多级目录已存在。** 真 GSI 的 `/vendor` 是
   **符号链接**（`stat` 显示 Type: symlink, Size 7），debugfs `cd` 进不去、`write` 静默落别处、
   读回 0 B。现在 `dir_kind()` 先分辨 dir/link/missing，落点只认真目录；
   设备级 manifest 也改投 `/etc/z1_device_manifest.xml` 中转（绝不覆盖 AOSP 的
   `/etc/vintf/manifest.xml`），由交棒脚本在运行时放进可写的 `/vendor/manifest.xml`
   （`RESULT_STEP_manifest=PLACED`）。
4. **A9 `hwservicemanager.rc` 里本来就有 `disabled`。** 真 GSI 原生就是这样
   （`class animation` + `onrestart class_restart hal/early_hal`），不是 stock 线那套代偿。
   所以这条判据的**归因**要改准：它表示"服务待启用"，不表示"stock 残留没撤"；
   处置动作不变（adapter 去掉 `disabled`，改造后镜像里就没有了），
   验收器仍会在未改造的镜像上报它 —— 因为最终镜像里 hwservicemanager 必须能起来。

## 4. 这份包现在能拿到什么板上真值（以及不能声称什么）

能拿到：`[a9hand]` 的分区识别（按 scatter 字节数认 android）、`by-name/*` 建立、只读挂载真 A9 ext4、
`RESULT_STEP_vendor`（tmpfs/bind/UNMOUNTED 三态）、`RESULT_STEP_fstab`（PLACED/MISS/OK/FAIL）、
`RESULT_STEP_selinux`（A9 GSI 只有 `plat_sepolicy.cil`，无 precompiled → 期望 NOPOLICY）、
以及 `[a9dev]/[a9probe]/[a9cfg]` 三段既有证据。

**不能声称**：安卓界面起来了。§2 那两个二进制到位之前，这条链不可能进 second-stage，
所以本目标仍未达成，我不把它标记完成。

## 5. 复现命令

```sh
cd <工作区根>
# 取料（代理口 + 完整性自证）
curl -sSL -o out/gsi_v123/system.img.xz "https://gh-proxy.com/https://github.com/phhusson/treble_experimentations/releases/download/v123/system-arm-aonly-vanilla-nosu.img.xz"
xz -t out/gsi_v123/system.img.xz && xz -dk -c out/gsi_v123/system.img.xz > out/gsi_v123/system.img
python3 a9_wt/tools/z1/z1_a9_sparse2raw.py out/gsi_v123/system.img out/gsi_v123/system.raw.img
# 裁剪 + 收缩（内容层改动都在 ADAPT_REPORT/本文件里留痕，原始 xz 保留可回溯）
sudo mount -o loop,rw out/gsi_v123/system.raw.img /mnt && sudo rm -rf /mnt/{lib/vndk-26,lib/vndk-27,framework/oat} && sudo umount /mnt
e2fsck -fy out/gsi_v123/system.raw.img && resize2fs -f out/gsi_v123/system.raw.img 227000
# 改造 + 出片
python3 a9_wt/tools/z1/z1_a9_mainline_system.py --system out/gsi_v123/system.raw.img --out out/a9sys_gsi
```
